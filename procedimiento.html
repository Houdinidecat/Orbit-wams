1. Desarrollo del sitio

Órbita utiliza Python con Flask para el servidor, SQLite para la base de datos y HTML5, CSS3 y JavaScript para la interfaz. El servidor entrega las páginas de dist/ y procesa las operaciones mediante la API /api/misiones.

  • Contenedor: toda la interfaz se agrupa dentro de <div id="contenedor">.
  • Header: un <div id="header" role="banner"> contiene la imagen del logo de Órbita a la izquierda.
  • Contenido: la página principal incluye un enlace al video We Are NASA en YouTube.
  • Footer: contiene el curso, nombre completo, código y correo de contacto.
  • Fondo: una imagen del centro galáctico de NASA, guardada en dist/assets/universo.jpg, se aplica mediante CSS.

2. Base de datos e interfaz gráfica

El Registro de misiones permite realizar estas operaciones con datos guardados en SQLite:

  1. Consultar todos los registros: ver y actualizar la lista de misiones.
  2. Consultar un registro individual: elegir Ver para abrir el detalle de una misión.
  3. Agregar registros: completar el formulario de nueva misión y guardar.
  4. Editar registros: seleccionar Editar, cambiar los campos y guardar.
  5. Eliminar registros: seleccionar Eliminar y confirmar el registro elegido.

schema.sql define la tabla misiones: id, nombre, destino, fecha, estado, notas, creado_en y actualizado_en. Los estados son Planificada, En curso y Completada; la fecha y las notas son opcionales.

La base de datos se prepara al iniciar el servidor. Localmente se guarda en data/orbita.sqlite3. Los registros permanecen entre ejecuciones mientras se conserve ese archivo. Esta aplicación usa datos de práctica compartidos y no incluye cuentas de usuario.

3. Plataforma y recurso de introducción

La plataforma seleccionada es Railway. Se consultó su Quick Start Tutorial como recurso de introducción equivalente a “Getting Started”, junto con las guías oficiales de Dockerfiles y volúmenes persistentes.

El Dockerfile incluido instala las dependencias de Python y ejecuta el servidor. Railway debe trabajar desde la raíz del repositorio para encontrarlo. Esta versión reemplaza la configuración estática anterior.

4. Ejecutar en tu computadora

Con Python 3.12 o posterior, abre PowerShell en la carpeta del proyecto y ejecuta, uno por uno:

  1. py -m venv .venv
  2. .\.venv\Scripts\python.exe -m pip install -r requirements.txt
  3. .\.venv\Scripts\python.exe app.py

Abre http://localhost:8080 y entra al registro. Mantén el servidor abierto mientras lo uses. Abrir el HTML con doble clic no ejecuta las operaciones de la base de datos.

5. Procedimiento de publicación consultado

Los pasos siguientes preparan una publicación futura, que realizará la estudiante por separado:

  1. Actualizar Houdinidecat/Orbit con el proyecto completo, conservando las carpetas dist/ y dist/assets/. Retirar los archivos antiguos que se hubieran aplanado en la raíz y el Staticfile anterior.
  2. Crear o actualizar el servicio de Railway desde ese repositorio y autorizar su acceso.
  3. Dejar Root Directory en la raíz y usar el Dockerfile. Retirar los comandos personalizados del despliegue estático anterior.
  4. Añadir un Volume al servicio, montado en /data. La imagen configura DATABASE_PATH=/data/orbita.sqlite3 para guardar allí SQLite y conservar los registros al volver a desplegar.
  5. Mantener una sola réplica. Desplegar y revisar los registros del servicio y el endpoint de salud /healthz.
  6. Generar un dominio, abrirlo y probar las cinco operaciones. Comprobar también que los registros permanezcan después de reiniciar.

GitHub conserva el código y Railway ejecuta la aplicación. No se necesita GitHub Pages.
